# Mobile authentication

Mobile authentication uses short-lived JWT access tokens and rotating refresh tokens. Login requires username/password plus a random app-installation UUID generated by the client; it does not use a hardware identifier. Tokens carry a `device_uuid` claim and every authenticated request verifies that the device belongs to the user and remains active.

Defaults are a 10-minute access lifetime and seven-day refresh lifetime. They are configurable with `MOBILE_ACCESS_TOKEN_MINUTES` and `MOBILE_REFRESH_TOKEN_DAYS`. Refresh rotation blacklists the previous refresh token. Logout blacklists the supplied refresh token. An administrator can revoke a `MobileDevice`; revocation immediately blocks access-token use and refresh.

Mobile login is independently throttled with `MOBILE_LOGIN_RATE` (default `5/minute`). Every authenticated request updates the registered device's last-seen timestamp. Login and bootstrap return the server version policy derived from `MOBILE_MINIMUM_SUPPORTED_VERSION` and `MOBILE_LATEST_VERSION`; malformed app versions are rejected.

Flutter stores tokens and its random installation identifier in platform secure storage, never Drift or SharedPreferences. Passwords are never persisted. First login is online-only. A previously established local session can be restored for 72 hours by default (`TNK_OFFLINE_SESSION_HOURS`), independently of JWT validity; an expired access token is refreshed online where possible and falls back to offline mode only inside that window. Revoked or invalid sessions are erased. Logout always erases local credentials, even if the server is unreachable.

Android application backups are disabled to prevent secure application state from being copied through platform backup services. The secure storage implementation uses the Android Keystore and iOS Keychain. Highly sensitive screen-capture controls remain subject to feature-level review when those screens are introduced.
